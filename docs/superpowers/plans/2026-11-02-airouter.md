# airouter 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在单个 Cloudflare Worker 上实现自用 AI 网关：三种对外 API 格式（OpenAI Chat / OpenAI Responses / Anthropic）、跨格式转换（含流式）、渠道失败转移、Responses 有状态会话、单管理员后台、API key 鉴权、失败日志，GitHub 一键部署。

**架构：** 单 Worker 同时承载 API（Hono）与前端静态资源（React 构建产物，`run_worker_first` 保证 `/v1/*`、`/admin/*` 先进 Worker）；数据全存 D1；网关核心按模型选渠道、按优先级失败转移，端点一致则透传、不同则经 ConvPair 转换器双向转换；Responses 会话状态（store / previous_response_id）由网关自管。

**技术栈：** TypeScript、Hono 4、React 18 + Vite 6 + Ant Design 5、Cloudflare Workers + D1 + Static Assets、vitest + @cloudflare/vitest-pool-workers。

**设计文档：** `docs/superpowers/specs/2026-11-02-airouter-design.md`（计划据此展开，施工者须同时阅读两份）

## 全局约束

- 全 TypeScript（strict）；运行时只用 Web 标准 API（fetch / ReadableStream / crypto.subtle），禁止 Node 专属 API 与原生依赖。
- 不依赖 Cloudflare 付费功能；`compatibility_date` 固定 `"2026-10-01"`。
- 所有导出函数、接口字段、类的字段必须有中文注释（项目全局规则）。
- 仓库为单根 `package.json`，包管理器用 npm（Deploy 按钮对 monorepo 支持不完整，禁止 workspaces）。
- **Git：每个任务结束只 `git add`，绝不 `git commit`，等用户人工提交**（用户全局规则，覆盖技能默认流程）。
- 测试全部跑在 @cloudflare/vitest-pool-workers 里（命令：`npx vitest run <文件>`）；集成测试用 `SELF.fetch` 进 Worker、`fetchMock`（来自 `cloudflare:test`）模拟上游。
- 前端构建产物目录固定 `dist/`；`npm run build` 必须从根目录一条命令完成。

## 评审重点（本计划最可能翻车的输入，测试已钉进对应任务）

1. **SSE 事件跨 TCP 分块断裂**：一条 `data:` 行被拆在两个 chunk、中文多字节字符被拆在字节边界 → 解析器必须正确缓冲。测试：Task 6 用人为切坏的 chunk 序列断言还原。
2. **工具调用跨格式转换**：OpenAI 的增量 `tool_calls`（index + arguments 片段）与 Anthropic 的 `input_json_delta`、Responses 的 `function_call` item 三方互转，id/index 对应错就丢调用。测试：Task 7/8/9 各自的方向。
3. **流已开始后上游中断**：不得再切渠道，必须以客户端格式优雅收尾（补错误事件 + 关流）。测试：Task 11 中断流。
4. **Anthropic 必填 `max_tokens` 缺省**：OpenAI 请求没带时必须默认补（4096），否则上游 400。测试：Task 7。
5. **图片多模态格式互换**：OpenAI `image_url:{url:"data:..."}` ↔ Anthropic `source:{type:"base64",...}`，data URL 的媒体类型与 base64 载荷要正确拆装。测试：Task 7。
6. **Responses 会话续接错位**：`previous_response_id` 展开的 items 顺序错、响应 id 改写漏改（流式事件里的 `response.id`/`response_id` 字段）、上游残留 `store` 造成双重存储 → 续接请求上下文丢失。测试：Task 10/11。
